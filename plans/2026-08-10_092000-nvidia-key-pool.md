# NVIDIA Key Pool — Automatic Load-Sharing Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a second (and optionally third) NVIDIA API key to Hermes' native credential pool so the `nvidia` provider auto-rotates across keys, splitting request load and avoiding per-key rate limits — zero downtime, no cron, no restarts.

**Architecture:** Hermes already supports "multiple credentials per provider pool and rotate automatically" (`hermes auth`). Today the `nvidia` pool has exactly 1 credential, env-fed from `NVIDIA_API_KEY` in `~/.hermes/.env`. Adding a second key via `hermes auth add nvidia --api-key …` (which works non-interactively) creates a 2-entry pool; Hermes rotates between entries per request and auto-marks exhausted keys until `hermes auth reset nvidia`. No code changes, no cron, no gateway restarts.

**Tech Stack:** Hermes CLI (`hermes auth`), `~/.hermes/auth.json` (SQLite-free JSON credential store), curl (key pre-verification), jq (rotation observation).

**Files:**

**Expected:** 2 rows — one `source=env:NVIDIA_API_KEY`, one `source=stored` (or similar) — both `base_url=https://integrate.api.nvidia.com/v1`.

## Risks, Tradeoffs & Open Questions

- **No literal cooldown:** pool rotation shares load per-request rather than 12h on/12h off. Both keys stay warm. This is what you picked — it beats cooldown for *burst* rate limits (a spike lands on both keys at once).
- **Env-fed entry quirk:** entry #1 is `env:NVIDIA_API_KEY`. If `.env` is edited later, the pool notices at next credential refresh; stored entries (#2/#3) are unaffected. Don't remove KEY-A from `.env` — it is the primary.
- **Rotation cadence:** exact trigger (per-request round-robin vs on-exhaustion) confirmed empirically in Task 3; plan already handles both outcomes.
- **KEY-C validity unknown** until user pastes it; Task 5 is gated on that.
- **gbrain keeps using its own key** (bashrc) for embeddings — unchanged, and now that key also aids Hermes. No action needed.
- **Open question:** if Task 3 shows rotation only happens on exhaustion (not per-request), consider whether that satisfies the rate-limit goal or whether a manual `hermes auth reset` rhythm is needed — revisit after Task 3 results.
